# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Thesis codebase implementing "Lizard" linearization (arXiv:2507.09025) applied to Llama-3.2-1B: replacing softmax attention with gated linear attention (GLA) plus a sliding-window softmax branch with sink tokens and RoPE (AWA), trained via two-stage distillation from the original model. No package/build system — standalone scripts in `src/` run inside the conda env in `envs/`. Setup and run steps for humans are in [README.md](README.md).

## Commands

```bash
make env                 # conda env create -f envs/distill_lizard_llama_3_2_1B.yaml
conda activate distill_lizard_llama_3_2_1B

make test                # PYTHONPATH=src pytest tests; CPU-only, tiny models
make test-kernels        # Triton kernels vs the PyTorch implementation (interpreter on CPU)
PYTHONPATH=src pytest tests/test_lizard.py::test_gla_matches_formula_loops
LIZARD_TEST_MODEL=meta-llama/Llama-3.2-1B PYTHONPATH=src pytest tests/test_lizard.py::test_whole_model_logits_unchanged_after_swap

make check               # Hugging Face and wandb access; make train depends on it
make train               # stage 1 + stage 2, needs CUDA; WANDB_MODE=disabled to skip wandb
make train STAGE=stage1   # or stage2 or both (default)
make train STAGE=stage2 STAGE1_CKPT=<path or name>   # stage 2 from a stage 1 checkpoint
make train CONFIG=configs/<name>.yaml   # any config; default configs/lizard-1b.yaml
make train-kernel         # train with the Triton kernels; KERNEL_CONFIG=configs/lizard-1b-mse1000-triton.yaml by default
make benchmark            # GLA kernel latency vs flash-linear-attention (Table 3); python src/benchmark.py --help
make evaluate            # lm-eval on the trained Lizard checkpoint
make xai                 # XAI figures: PyTorch and Triton runs (stage 1, stage 2) vs the teacher; make xai-curves first for W&B losses
make evaluate-llama      # same tasks on the unmodified teacher
make mmlu                # only the full MMLU 5-shot (--tasks mmlu)
make mmlu-fast           # MMLU 5-shot, 5 questions per subject (285); MODEL=llama for the teacher
make mmlu-fast CKPT=<path or name>   # on one stage 1 or stage 2 checkpoint (also for make evaluate)
make push                # upload src/ and the config to the Hugging Face repo in config
```

Run everything from the repo root: `out_dir` (default `checkpoints/`) is relative to the working directory. All hyperparameters and paths live in a YAML file in `configs/`, one file per experiment. Every script parses its arguments with `argparse`: the config path is positional, choices are options with `choices=` (so argparse rejects bad values): `python src/train.py <config> [--stage stage1|stage2|both] [--stage1-ckpt PATH]`, `python src/evaluate.py <config> [--model lizard|llama] [--tasks all|mmlu|mmlu-fast] [--checkpoint PATH]`, `python src/push_to_hub.py <config> [files ...]`, `python src/check.py <config>`. `main` functions take plain values, so tests call them directly.

## Config

[src/config.py](src/config.py) defines frozen dataclasses `Config` (every key of the YAML, plus `name` = file stem and `path`) and `Lizard` (`window`, `num_meta`, `feature_dim`, `backend`, passed to `LizardAttention` with `asdict`). `backend` is `torch` or `triton`; each `-triton` config is its torch config with only `backend` changed (a test checks this). `load(path)` reads the YAML, casts the float fields (PyYAML reads `1e-3` as a string), and builds the dataclasses, so missing or unknown keys raise `TypeError`. `cfg.torch_dtype` maps `dtype` to the torch dtype. `LIZARD_PARAMS` stays a module constant, not a config value. Code gets the `Config` object as a `cfg` argument; there is no global config.

## Architecture

- **`src/lizard_attention.py`** — pure-PyTorch, dense (materializes L×L) implementation. `hedgehog`, `gla`, `awa`, `sink_softmax` are free functions so tests can call them directly; `LizardAttention` is a drop-in for `LlamaAttention` (`forward(hidden_states, position_embeddings)` returns `(out, None)`, RoPE on the window branch only, no KV cache so generation needs `use_cache=False`). Weights stay in `cfg.dtype` (bfloat16); the Lizard math runs in at least float32. `from_llama` builds one from a Llama attention layer by copying q/k/v/o weights. With `backend="triton"`, `forward` calls `kernels.gla(fq, fk, v, logsigmoid(z))` and `kernels.swa(qr, kr, v, meta, window)` instead of `gla`/`awa`; `kernels` is imported lazily, so the torch backend works without Triton.
- **`src/kernels/`** — Triton kernels in bf16 (fp32 accumulation, bf16 outputs), each with a forward and a backward pass, tiled like flash attention (no L×L tensor):
  - `gla.py`: `gla(fq, fk, v, log_gamma, chunk=64)` is the chunkwise form of the paper's Section 4 reparameterization. `G = cumsum(log_gamma)` (autograd handles the cumsum, the logsigmoid and the `[B, L]` → `[B, H, L]` expand; per-head `[B, H, L]` gates also work). The paper absorbs `log C` into the features; over a whole sequence `exp(-G_t)` overflows, so `G` is measured from the chunk boundary: `start = G[n·BT-1]` (0 for the first chunk), `end = G[last of chunk]`, `Q~ = fq·exp(G_i - start)`, `K~ = fk·exp(end - G_t)`, every factor ≤ 1 (`_rescale` masks padding with `-inf`). Forward: `_gla_fwd_h` (grid F-blocks × D-blocks × B·H, sequential over chunks) stores the state `S_n = Σ K~^T v` (bf16) and `z_n = Σ K~` (fp32) at each chunk start; `_gla_fwd_o` (grid chunks × B·H) adds `Q~ S_n` and the intra-chunk part `(fq fk^T)·exp(G_i - G_t)` (decay applied after the GEMM; absorbing it would overflow inside a chunk). The row sum uses the same bf16-rounded intra weights as the numerator, so a single token gives `y = v` and zero `fq`/`fk`/gate gradients. With `SAVE` (any input needs grad) it also stores fp32 `y` and `den`; `delta = dy·y` uses the fp32 `y`, because the bf16 `y` makes `dy·v_i - delta` pure rounding under strong decay (10% gradient error vs 0.5%). Backward: `_gla_bwd_dh` runs the reverse recurrence for `dS_n`, `dz_n`; `_gla_bwd_dqkv` gives dfq, dfk, dv per chunk; `dg = Σ(fq·dfq - fk·dfk)` in PyTorch. O(L) compute and memory. Kernels are autotuned over `num_warps` (4, 8) × `num_stages` (1, 2, 3) on GPU (one config under the interpreter); configs that exceed shared memory are skipped by the autotuner.
  - `swa.py`: `swa(q, k, v, meta, window)` runs an online softmax over the window, starting from the sinks, and saves the log-sum-exp; the sink gradient `-Σ exp(b_j - lse)·delta` is computed in PyTorch.
  - `dot.py`: `dot(a, b, F32)` casts both operands to bf16 (tensor cores on GPU); under `TRITON_INTERPRET=1` it then casts to fp32, because the interpreter's bf16 `tl.dot` is wrong (numpy has no bf16). The interpreter also truncates fp32→bf16 casts, so its errors are slightly larger than on a GPU. SWA blocks (64, 64).
- **`src/benchmark.py`** — latency of `kernels.gla` vs flash-linear-attention's `chunk_gla` (paper baseline, gate per key dim) and `chunk_simple_gla` (gate per head), random inputs in each kernel's native layout (`[B, H, L, D]` for ours, `[B, T, H, D]` for FLA), `triton.testing.do_bench` medians, `--backward` for forward + backward, `--plot` for a Figure 5 bar chart. Defaults are Table 3 (B×L in 16×2048, 16×4096, 16×8192, 32×8192; 32 heads; head dim 128); `PAPER` holds the paper's speedups. Inputs are built per method and freed, OOM prints `OOM`. FLA is imported lazily (`pip install fla-core`); without it only Lizard is timed. Needs CUDA, no model.
- **`src/xai.py`** — XAI for the thesis, subcommands `compute`, `curves`, `plot`. `compute <config> --checkpoint --label PyTorch|Triton --stage stage1|stage2 --out` loads the teacher (`train.load_llama`) and the checkpoint (`evaluate.load`, so the config's backend decides torch or Triton), runs `held_out` sequences (the alpaca examples after `num_examples` of the training shuffle, packed like training), captures each teacher attention layer's (input, RoPE, output) and feeds that input to the Lizard layer. Per layer: relative MSE of the layer output (the stage 1 target) per query span (`SPANS` 0-127, 128-511, 512-1023, 1024-2047, all); per head, TV distance of the attention weights against the teacher, mass outside the window (teacher and Lizard) and window-branch share, with Lizard weights `A_gla + alpha * A_window` rebuilt densely from `lizard_attention` functions in head groups of 8 and rows normalized (as lolcats' `scripts/attention_weights.py`), and `weights_check` = relative error of `A @ v` against `gla + alpha * awa`; mean gate, median `1/(1-gamma)`, alpha, mean sink; 256×256 weight crops of the first sequence for `--maps`. `before_o_proj` and `thesis_results` also write the lolcats XAI formats to `<out dir>/thesis/{xai-layer-wise-mse,xai-position-mse,xai-branch-fit}/<out name>` (definitions of lolcats' `scripts/layer_mse.py`, `position_mse.py`, `branch_fit.py`): teacher `y_true = softmax(q k^T) v` with the teacher's own q/k/v (RoPE, causal), Lizard `G + alpha W` before `o_proj`, per head and per bucket (`EDGES` 0, 128, 512 → `0–127`, `128–511`, `512–2047` with en dashes, plus `all`), `loss = mse_factor × mean layer mse`; branch fit with float64 Gram matrices of `[y_true, G, W, WR, trained]` (WR = softmax with RoPE over the window without sinks), `solve` = pinv least squares per head and set (`SETS`), `trained` = fixed output error. The thesis repo (jku-thesis-drafts, `src/plots/make_plots.py`) reads these. Default `--sequences 16` (32,768 tokens, as the lolcats validation data). `weights` writes lolcats' `scripts/attention_weights.py` JSON (crops `[sample][layer][head]` of `teacher`, unnormalized `lizard` = `A_gla + alpha A_window`, `gla`; last `--queries` queries × first and last `--queries` keys; per-head `head_metrics` over queries ≥ window) on `lolcats_sample`: the first 200 alpaca-cleaned train examples with lolcats' `PROMPTS` template (BOS on the prompt, `output + eos` without), packed to `--seq-len` 1024, first chunk — the same tokens as lolcats' validation sample; `make xai-weights`. `curves` reads `<stage>/loss` histories from W&B by run display name. `plot` writes `layer_mse`, `position_mse`, `attention_tv`, `position_tv`, `window_share`, `gate_memory`, `attention_maps`, `evaluation` (Table 9 from `evaluate.py` JSONs plus `evaluate.PAPER`), `training_loss` PNGs and `xai.md`; one panel per stage, fixed colors per label (`COLORS`). Make targets `xai`, `xai-compute`, `xai-curves`, `xai-plot` with run-name variables `TORCH_STAGE1/2`, `TRITON_STAGE1/2` (defaults: the thesis runs).
- **`tests/test_xai.py`** — the weights rebuild reproduces the layer output, identical weights give zero distance, and `compute` + `plot` for both labels and stages on a tiny Llama (teacher, loader and tokenizer monkeypatched).
- **`src/check.py`** — preflight before training: `CHECKS` is a list of `check_*(api, cfg)` functions (HF login, `auth_check` read on `model_name` and `dataset_name`, `create_repo` + `auth_check(write=True)` on `hf_repo`, wandb `Api().viewer`, skipped when `WANDB_MODE` is `disabled`/`offline`). `check_kernels` imports Triton and requires CUDA only for `backend: triton`. `main` prints `[ok]`/`[fail]` for each and returns the number of failures; the exit code is 1 if any failed, so `make train: check` stops.
- **`src/train.py`**:
  - Stage 1 builds standalone student `LizardAttention` layers (not inserted into the model), captures each teacher attention layer's (input, RoPE cos/sin, output) with forward hooks, and trains only Lizard params with lolcats' loss: the mean squared error of each layer (`F.mse_loss`, mean over elements), averaged over layers and multiplied by `cfg.mse_factor` (1 in the default config; lolcats uses 1000), backpropagating layer by layer. Returns a state dict keyed like `model.layers.{i}.self_attn.*`.
  - Stage 2 swaps Lizard into a fresh model (`to_lizard`), loads the stage 1 params, wraps with LoRA on q/k/v, re-enables Lizard params (PEFT freezes them), trains with causal-LM loss, then `merge_and_unload()` so the saved checkpoint loads with `strict=True`.
  - `main(cfg, stage)` names the run `<cfg.name>-<start time>` (also the wandb name), copies the YAML to `cfg.out_dir/<run>.yaml`, and `save` writes `<run>-stage1.pt` and `<run>-stage2.pt` right after each stage. Each of the three files goes to `cfg.hf_repo` with `push_to_hub.upload`. If `torch.save` to disk raises (`OSError`/`RuntimeError`, e.g. a full disk: `basic_ios::clear: iostream error`), `save` deletes the partial file, serializes to a `BytesIO` and uploads that (`upload(path, repo, data)`); `tests/test_train.py` covers both paths. `stage` is `stage1`, `stage2` or `both`. `stage2` alone loads its stage 1 params with `load_stage1(cfg)` from `cfg.stage1_ckpt` (asserted to be set). `--stage1-ckpt` overrides the YAML value with `dataclasses.replace`. If the file does not exist locally, `fetch` downloads `cfg.hf_repo/<file name>` into `cfg.out_dir` with `hf_hub_download`.
  - `train` prints the step count first (`len(loader) // grad_accum` steps per epoch × `epochs`) and shows a tqdm bar over optimizer steps, refreshed every second on a terminal and every 30 s otherwise (log files). `log` returns the bar postfix (loss, lr, grad norm, mean `alpha_blend`, mean `meta_tokens`) and sends the same values to wandb.
  - `is_lizard` matches parameter names by exact dotted component against `config.LIZARD_PARAMS` — the single source of truth for which params are Lizard-owned.
- **`src/evaluate.py`** — wraps the model in lm-eval's `HFLM` (`add_bos_token=False`, as the lolcats harness) and loads `--checkpoint`, or else the newest `cfg.out_dir/<cfg.name>-*-stage2.pt`, through `train.fetch` (downloads from `cfg.hf_repo` if missing). A checkpoint with only Lizard keys (stage 1) loads with `strict=False` on top of `to_lizard(teacher)`, asserting no unexpected keys and no missing Lizard keys; any other checkpoint loads with `strict=True`. Runs the paper's Table 9: PIQA/ARC-e/WinoGrande `acc`, ARC-c/HellaSwag `acc_norm` zero-shot, MMLU 5-shot. `run_mmlu` sets `log_samples=True` and `letters` counts the predicted letter (argmax of the four log-likelihoods in `filtered_resps`) and the gold letter over the `mmlu_*` samples; the JSON has `mmlu_letters` (`pred`, `gold`). `--tasks mmlu` runs only the full MMLU. `summarize` scores MMLU as the unweighted mean over the 57 leaf subjects (lolcats' definition, not lm-eval's size-weighted group score) and Avg. over the five zero-shot tasks only, as the paper does. `PAPER` holds the paper's teacher and Lizard values. `cfg.eval_limit` limits questions per task. The `mmlu-fast` mode runs only `run_mmlu(lm, FAST_MMLU_LIMIT=5)`: lm-eval applies `limit` to each of the 57 subject tasks, so it scores 285 questions, as lolcats' `eval.sh --limit 5` (lm-eval 0.4 takes the first 5 test questions; lolcats' old harness took the first 5 after a seed-42 shuffle). Results go to `<cfg.name or checkpoint stem>-eval-<model>-<all|mmlu-fast>.json`. Right padding in lm-eval's loglikelihood batches keeps Lizard (which ignores the padding mask) correct for batch sizes above 1. The configs use `eval_batch_size: 1` (as lolcats): the dense L×L Lizard attention runs out of memory on a 24 GB A10 with 8 long 5-shot MMLU prompts per batch.
- **`tests/test_evaluate.py`** — tests of `summarize`, of the `PAPER` averages, and of `load` with a stage 1 and a stage 2 checkpoint.
- **`tests/test_kernels.py`** — correctness of the kernels against the PyTorch implementation (`lizard_attention.gla`/`awa` in float32 on the same bf16 inputs) for the forward and backward pass, small and default chunk/block sizes, gates per head, strong decay (total log gate below -1000, beyond the exp range), the no-grad path, no sinks, and a whole `LizardAttention` layer (torch vs triton backend, outputs and every parameter gradient). Tolerances: 1e-2 relative for outputs, 3e-2 relative plus 1e-3 absolute for gradients. `tests/conftest.py` sets `TRITON_INTERPRET=1` before any import when there is no GPU.
- **`tests/test_check.py`** — the checks with fake HF and wandb clients: all pass, and failures are counted.
- **`tests/test_config.py`** — the default YAML loads with the right types, and an unknown key fails.
- **`tests/test_lizard.py`** — slow loop/recurrent versions of every formula (`gla_loop`, `gla_recurrent`, `awa_loop`, `rope_loop`, `lizard_loop`) plus tiny-config helpers, and the tests. The loops are the ground truth; tests assert `rel_err < 1e-10` in float64 against them.
